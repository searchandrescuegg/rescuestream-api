# Data Model: Multi-Tenant Platform

**Feature**: 003-multi-tenant-platform
**Phase**: 1
**Date**: 2026-04-21
**Reference**: `research.md` (§1 hashing, §3 sessions, §6 tenancy, §7 optimistic concurrency, §9 audit, §10 migration).

All columns use PostgreSQL types. UUIDs are v4, generated by the application (not the DB) so they can be returned in the mutation request's response without a second round-trip.

### 1.4 `organization_memberships`

| Column | Type | Null | Default | Notes |
|--------|------|------|---------|-------|
| `id` | uuid | NO | | PK |
| `user_id` | uuid | NO | | FK → users(id) ON DELETE CASCADE |
| `organization_id` | uuid | NO | | FK → organizations(id) ON DELETE CASCADE |
| `team_id` | uuid | YES | | FK → teams(id) ON DELETE RESTRICT; NULL for org-admins who are not on any team |
| `role` | varchar(16) | NO | | CHECK IN ('org-admin','member') |
| `joined_at` | timestamptz | NO | `now()` | |

**Indexes**:

- UNIQUE on `user_id` — enforces one-org-per-user (FR-002).
- `(organization_id, team_id)`.
- `(organization_id, role)` for admin listing.

**Invariants**:

- `role = 'member'` ⇒ `team_id IS NOT NULL`. Enforced by CHECK constraint and by the service layer.
- Team deletion is a coordinated service-layer transaction (not a FK cascade): (a) delete every `organization_memberships` row where `team_id = deleted_team AND role = 'member'`, (b) `RevokeAllForUser` on each of those users' sessions, (c) `UPDATE` any org-admin rows that happen to carry the deleted team as `team_id` to `team_id = NULL`, (d) `DELETE` the team. The FK is `ON DELETE RESTRICT` so that forgetting step (a) surfaces a loud error rather than silently corrupting the CHECK invariant.

### 1.9 `device_keys`

| Column | Type | Null | Default | Notes |
|--------|------|------|---------|-------|
| `id` | uuid | NO | | PK |
| `device_id` | uuid | NO | | FK → devices(id) ON DELETE CASCADE |
| `key_hash` | varchar(64) | NO | | HMAC-SHA256 hex; see research §1 |
| `slot` | varchar(16) | NO | | CHECK IN ('primary','secondary') |
| `status` | varchar(16) | NO | `'active'` | CHECK IN ('active','revoked') |
| `created_at` | timestamptz | NO | `now()` | |
| `expires_at` | timestamptz | YES | | Nullable; no expiry by default |
| `revoked_at` | timestamptz | YES | | Set when status flips to 'revoked' |
| `last_used_at` | timestamptz | YES | | Touched on publish-auth success |

**Indexes**:

- UNIQUE on `key_hash` (hot path — used on every mediamtx publish-auth).
- UNIQUE on `(device_id, slot) WHERE status = 'active'` — enforces one active key per slot (supports overlap between primary and secondary).

**Invariants**:

- Plaintext is never stored; only `key_hash`.
- Service layer enforces: a device can have at most 2 active keys at any time (one per slot).

### 1.10 `rooms`

| Column | Type | Null | Default | Notes |
|--------|------|------|---------|-------|
| `id` | uuid | NO | | PK |
| `organization_id` | uuid | NO | | FK → organizations(id) ON DELETE CASCADE |
| `team_id` | uuid | YES | | FK → teams(id) ON DELETE RESTRICT; NULL when scope='org' |
| `name` | varchar(200) | NO | | |
| `description` | varchar(1000) | YES | | |
| `scope` | varchar(16) | NO | | CHECK IN ('org','team') |
| `lifecycle_state` | varchar(16) | NO | `'active'` | CHECK IN ('active','archived') |
| `archive_after` | interval | NO | `'30 days'::interval` | Admin-configurable per room |
| `last_activity_at` | timestamptz | NO | `now()` | Updated on stream start/end, entry |
| `default_device_policy` | varchar(32) | NO | `'any-org-device'` | CHECK IN ('any-org-device','allowlist') |
| `acl_combinator` | varchar(8) | NO | `'or'` | CHECK IN ('and','or') |
| `version` | bigint | NO | `1` | Monotonic; see research §7 |
| `created_by_user_id` | uuid | NO | | FK → users(id) ON DELETE RESTRICT |
| `created_at` | timestamptz | NO | `now()` | |
| `updated_at` | timestamptz | NO | `now()` | |

**Indexes**:

- `(organization_id, lifecycle_state, last_activity_at DESC)` for dashboard listing.
- `(organization_id, team_id)` for team-scoped room lookups.

**Invariants** (enforced at service + DB level):

- `scope = 'org'` ⇒ `team_id IS NULL`.
- `scope = 'team'` ⇒ `team_id IS NOT NULL AND teams.organization_id = rooms.organization_id`.
- Any mutation MUST increment `version` and MUST use the optimistic-concurrency guard (research §7).
- `lifecycle_state = 'archived'` rejects new streams at the service layer.

### 1.11 `room_acl_rules`

| Column | Type | Null | Default | Notes |
|--------|------|------|---------|-------|
| `id` | uuid | NO | | PK |
| `room_id` | uuid | NO | | FK → rooms(id) ON DELETE CASCADE |
| `type` | varchar(8) | NO | | CHECK IN ('team','tag','user') |
| `target_id` | uuid | NO | | Points to teams/tags/users depending on `type` |
| `created_at` | timestamptz | NO | `now()` | |

**Indexes**:

- `(room_id)` for enumerate-on-evaluate.
- `(type, target_id)` for reverse lookup ("which rooms include team X?").

**Invariants**:

- Polymorphic integrity is enforced at the service layer (validate the target exists in the right table before insert) plus an optional trigger-based CHECK for belt-and-suspenders. Full FK is infeasible without a polymorphic join.
- ACL replacement is transactional: `DELETE WHERE room_id = $1; INSERT ...; UPDATE rooms SET version = version + 1`. All three in one tx.

### 1.13 `sessions`

| Column | Type | Null | Default | Notes |
|--------|------|------|---------|-------|
| `id` | uuid | NO | | PK |
| `user_id` | uuid | NO | | FK → users(id) ON DELETE CASCADE |
| `hmac_key_id` | varchar(32) | NO | | Sent as `X-API-Key`; UNIQUE; 16 bytes base32 |
| `hmac_secret_hash` | varchar(64) | NO | | Peppered HMAC of the secret (same scheme as device keys) |
| `created_at` | timestamptz | NO | `now()` | |
| `expires_at` | timestamptz | NO | | |
| `last_used_at` | timestamptz | NO | `now()` | |
| `revoked_at` | timestamptz | YES | | |
| `revoked_reason` | varchar(64) | YES | | e.g. `'admin-force-logout'`, `'role-changed'`, `'member-removed'`, `'self-logout'` |
| `client_ip` | inet | YES | | Captured at creation for forensics |
| `user_agent` | varchar(500) | YES | | Captured at creation |

**Indexes**:

- UNIQUE on `hmac_key_id`.
- `(user_id) WHERE revoked_at IS NULL` — fast batch-invalidation.

**Invariants**:

- Once `revoked_at IS NOT NULL`, the session is permanently dead; no resurrection.
- A session is valid only when `revoked_at IS NULL` AND `expires_at > now()`.

**Value vocabulary additions**: `action` and `resource_type` accept the new verbs listed in research §9. No enum type at DB level; enforced by the service layer (as today).

**New indexes**:

- `(actor_user_id, timestamp DESC)` for per-user forensics.

## 4. Views and materialized views

### 4.1 View: `members_with_tags`

```sql
CREATE VIEW members_with_tags AS
SELECT
  om.organization_id,
  om.user_id,
  om.team_id,
  om.role,
  coalesce(array_agg(uta.tag_id) FILTER (WHERE uta.tag_id IS NOT NULL), '{}') AS tag_ids
FROM organization_memberships om
LEFT JOIN user_tag_assignments uta ON uta.user_id = om.user_id
GROUP BY om.organization_id, om.user_id, om.team_id, om.role;
```

Used by the ACL evaluator and the preview endpoint. No materialization at current scale.

## 5. Migration sequence (migration files)

### 5.1 `000003_v2_structure.up.sql`

1. Create `users`, `organizations`, `teams`, `organization_memberships`, `super_admins`, `tags`, `user_tag_assignments`, `devices`, `device_keys`, `rooms`, `room_acl_rules`, `room_devices`, `sessions`.
2. Add `organization_id` / `actor_user_id` to `audit_logs` (nullable initially).
3. Add `organization_id`, `room_id`, `device_id` to `streams` (nullable initially).
4. Seed the default organization:
   - INSERT `users` row `(id = gen_random_uuid(), email = 'platform@rescue.stream', google_subject = NULL, display_name = 'Platform')` as the placeholder creator.
   - INSERT `organizations (name='RescueStream Default', slug='default', created_by_user_id=<placeholder>)`.
5. Backfill `users` from distinct non-null `audit_logs.actor` values (where `actor` looks like an email).
6. Bootstrap `super_admins` from the `SUPER_ADMIN_EMAILS` env var passed into the migration command.

### 5.2 `000004_v2_backfill.up.sql`

1. UPDATE `audit_logs` SET `organization_id = <default>`, `actor_user_id = <matching user>`.
2. UPDATE any existing `streams` rows (if preserved) to the default org; otherwise `TRUNCATE streams` per FR-034.
3. `DROP TABLE stream_keys CASCADE`; `DROP TABLE broadcasters CASCADE`.

### 5.3 `000005_v2_constraints.up.sql`

1. Do NOT `ALTER TABLE audit_logs ALTER COLUMN organization_id SET NOT NULL` — `organization_id` MUST remain nullable because super-admin platform events (e.g., `org.created`) don't belong to any org. The service layer enforces: every mutation emitted with a recognizable organization context carries an `organization_id`; only super-admin-authored platform events legitimately carry NULL.

2. `ALTER TABLE streams ALTER COLUMN organization_id SET NOT NULL` etc. for streams.
3. Add partial indexes documented above.
4. Add CHECK constraint on `organization_memberships` for `role = 'member' ⇒ team_id IS NOT NULL`.

### 5.4 Down migrations

- `.down.sql` counterparts DROP the new structure.
- Do not attempt to reconstruct `broadcasters` / `stream_keys` — clean break.

## 7. Invariants enforced by the service layer (summary)

1. One organization per user — `UNIQUE(user_id)` on `organization_memberships`.
2. Every tenant-scoped query in a repository takes `orgID uuid.UUID`.
3. Super-admin must always be ≥ 1 (block deletion of the last row).
4. `role = 'member'` ⇒ `team_id IS NOT NULL`.
5. Room `scope = 'team'` ⇒ `team_id` populated and points to a team in the same org.
6. Room ACL rule `target_id` exists in the table matching `type`, and belongs to the same org as the room.
7. Device key plaintext never written anywhere durable; only `key_hash` stored.
8. Session is valid only when `revoked_at IS NULL` AND `expires_at > now()`.
9. Every room mutation increments `version`; stale version causes rejection (SC-014).
10. Audit log entries for v2 resources always carry `organization_id` except for super-admin-authored platform events (where it is NULL by design).
